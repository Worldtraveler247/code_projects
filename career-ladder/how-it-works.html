Career Ladder — How It's Built

Role-by-role progression maps for Cloud Security, Cybersecurity, DevSecOps, and AI-ML — civilian and government tracks with 2025 salary data.

Overview

Career Ladder is a zero-dependency static app that maps six progression levels (L1–L6) across four cybersecurity/tech disciplines. Each track lives in its own JSON file. A tab switcher drives lazy loading — tracks are fetched on first click and cached in a Map so subsequent visits are instant. A Civ/Gov toggle re-renders from the same cached data using 2025 OPM GS pay table salaries for government roles and realistic market comps for civilian roles. Everything renders via DOM construction — no innerHTML, no framework, no build step.

Tech Stack

HTML CSS JavaScript (ES Modules) JSON
  • HTML — single page; ARIA tablist/tab/tabpanel pattern with roving tabindex and keyboard nav (ArrowLeft/ArrowRight)
  • CSS — design token system (:root variables), CSS custom properties for card theming, responsive 600px breakpoint
  • JavaScript (ES Modules) — three modules: main.js (tab/mode orchestration), render.js (DOM builder), utils.js (salary bar math, chip builder, hash routing)
  • JSON — one file per track; each has a levels[] array with civ and gov sub-objects for dual-mode rendering

How Each Part Works

js/main.js — tab switching with cache and race guard

switchToTrack() sets an inflightTrackId before the async fetch. When the response arrives, it checks whether inflightTrackId still matches — if the user clicked a different tab while waiting, the stale response is discarded silently. Tracks are stored in a Map keyed by track ID; cache hits skip the network entirely. 

const trackCache = new Map();
let inflightTrackId = null;

async function switchToTrack(trackId) {
  currentTrackId = trackId;
  inflightTrackId = trackId;        // mark this fetch as current

  activateTab(/* matching tab button */);

  const data = await loadTrack(trackId);
  if (inflightTrackId !== trackId) return; // superseded by a newer click
  if (!data) return;                        // network error — already shown

  renderTrack(data, currentMode);
  trackToHash(trackId);             // push #cloud-security etc. to URL
}

async function loadTrack(trackId) {
  if (trackCache.has(trackId)) return trackCache.get(trackId);

  const response = await fetch(`data/${trackId}.json`);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const data = await response.json();
  trackCache.set(trackId, data);    // cache forever for this session
  return data;
}

js/render.js — DOM construction, no innerHTML

renderTrack(data, mode) clears the container with replaceChildren() (no XSS risk vs. innerHTML = ''), then builds one <article class="level-card"> per level entry. The mode parameter ('civ' or 'gov') selects which sub-object to read for salary and role data. Gov mode appends an extra GS range + clearance block. 

export function renderTrack(data, mode) {
  const container = document.getElementById('ladder-container');
  container.replaceChildren();      // safe clear

  for (const level of data.levels) {
    const modeData = level[mode];   // level.civ or level.gov

    const article = document.createElement('article');
    article.className = 'level-card';

    // salary bar: left% and width% computed from SALARY_SCALE=250_000
    const { left, width } = salaryBarWidth(modeData.salary_min, modeData.salary_max);
    const fill = document.createElement('span');
    fill.className = 'salary-bar__fill';
    fill.style.left = left;   // e.g. "26.0%"
    fill.style.width = width; // e.g. "14.0%"

    // gov-only block
    if (mode === 'gov') {
      const gsSpan = document.createElement('span');
      gsSpan.textContent = `GS Range: ${modeData.gs_range}`;
      // ...
    }
    // skills, certs as chip groups; next_steps + milestone in callout box
  }
}

js/utils.js — salary bar math and hash routing

salaryBarWidth() maps a salary range onto a percentage-width bar relative to a SALARY_SCALE of $250K. Both inputs are clamped to [0, SALARY_SCALE] before computing, so bad JSON can't produce negative widths or overflow. hashToTrack() reads window.location.hash and validates it against a private VALID_TRACKS allowlist to prevent arbitrary fetch paths from URL manipulation. 

export const SALARY_SCALE = 250_000;

const VALID_TRACKS = new Set(['cloud-security','cybersecurity','devsecops','ai-ml']);

export function salaryBarWidth(salary_min, salary_max, scale = SALARY_SCALE) {
  const lo = Math.max(0, Math.min(salary_min, scale));
  const hi = Math.max(0, Math.min(salary_max, scale));
  return {
    left:  `${((lo / scale) * 100).toFixed(1)}%`,
    width: `${(((hi - lo) / scale) * 100).toFixed(1)}%`,
  };
}

export function hashToTrack() {
  const raw = window.location.hash.replace('#', '');
  return VALID_TRACKS.has(raw) ? raw : 'cloud-security'; // default
}

data/*.json — dual-mode schema

Each track file has a flat levels[] array. Every level carries both a civ and gov sub-object so the same JS can render either mode from the same cached payload. Government salaries are based on 2025 OPM GS pay tables with the Rest of U.S. locality adjustment (17.06%). L6 gov uses the SES ES-6 pay band ($155,700–$226,300).

Replicate It Yourself

  1. Design a dual-mode JSON schema. Give every level two sub-objects (civ and gov) with matching fields. Store shared data (skills, certs, next_steps) at the level root so a mode switch is just swapping one sub-object reference.
  2. Wire a tablist with ARIA and a Map cache. Use role="tablist", role="tab" with aria-selected, and role="tabpanel" with aria-labelledby. Store fetched JSON in new Map() keyed by track ID. On tab click, check the Map before fetching. Reference: ARIA Tabs Pattern (W3C).
  3. Guard against race conditions. Set an inflightTrackId variable before every fetch. After await, check it still matches before rendering — rapid tab clicks otherwise cause stale data to overwrite the current view.
  4. Build cards with DOM APIs, not innerHTML. Use document.createElement and container.replaceChildren(). This eliminates the XSS surface you'd get from template-literal HTML strings, and the browser doesn't have to re-parse a string. Reference: MDN replaceChildren.
  5. Map salaries to a percentage bar. Pick a scale constant (e.g. SALARY_SCALE = 250_000). Compute left = lo / scale * 100 and width = (hi - lo) / scale * 100. Clamp inputs first so no bad JSON value produces a negative or overflowing bar.
  6. Add hash-based routing with an allowlist. Read window.location.hash for the initial track, but validate against a Set of known track IDs before using the value in a fetch() call. This prevents URL manipulation from driving arbitrary network requests.
  7. Deploy to GitHub Pages. Push to main, go to repo Settings → Pages → Source: Deploy from branch → main / (root). No build step, no bundler needed — ES modules load directly in the browser. Reference: GitHub Pages docs.
