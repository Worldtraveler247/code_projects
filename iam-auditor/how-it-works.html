IAM Auditor — How It's Built

A Python CLI that audits AWS IAM for security risks and reports findings with CI-gate semantics.

Overview

IAM Auditor is a command-line tool that connects to your AWS account and checks for common IAM misconfigurations — starting with access keys that haven't been used in 90+ days. It outputs a human-readable table or JSON, exits with code 1 when findings exist (so a CI pipeline can gate on it), and never needs more than read-only IAM permissions. Built as a learning-in-public project while studying for AWS Security Specialty — each check maps to a real CIS Benchmark or AWS Well-Architected Framework control.

Tech Stack

Python 3.12 boto3 moto pytest ruff mypy hatchling

Architecture

The design uses a Check ABC pattern: every security check is a class that implements one method, run(iam_client) -> Iterator[Finding]. The CLI wires all registered checks to a reporter. Adding a new check means dropping one file — no changes to the runner. 

# The three-layer architecture:
#   cli.py       → orchestrates: parse args → build checks → run → report
#   checks/      → each file is one security control, yields Finding objects
#   reporters/   → terminal (table) or JSON output

# models.py — shared data contract
from dataclasses import dataclass
from enum import Enum

class Severity(str, Enum):
    HIGH   = "HIGH"
    MEDIUM = "MEDIUM"
    LOW    = "LOW"

@dataclass(frozen=True)
class Finding:
    check_id:    str       # e.g. "IAM-001"
    severity:    Severity
    resource:    str       # ARN or human-readable identifier
    message:     str       # one sentence: what's wrong
    remediation: str       # one sentence: how to fix it

How Each Part Works

checks/base.py — the Check interface

Every security check inherits from Check and implements run(). The CLI discovers all registered checks by iterating a list — no magic plugin system needed at this scale. Using an abstract base class means mypy enforces the contract at type-check time, not at runtime. 

from abc import ABC, abstractmethod
from collections.abc import Iterator
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from mypy_boto3_iam import IAMClient

from iam_auditor.models import Finding

class Check(ABC):
    @abstractmethod
    def run(self, iam_client: "IAMClient") -> Iterator[Finding]:
        """Yield one Finding per policy violation found."""
        ...

checks/unused_access_keys.py — IAM-001

Calls ListUsers, then for each user calls ListAccessKeys and GetAccessKeyLastUsed. A key is flagged if it's Active and either was never used or was last used more than max_age_days ago. The threshold is configurable so CI pipelines can tighten it (e.g., 30 days for high-compliance environments). 

class UnusedAccessKeysCheck(Check):
    def __init__(self, max_age_days: int = 90) -> None:
        self.max_age_days = max_age_days

    def run(self, iam_client: "IAMClient") -> Iterator[Finding]:
        cutoff = datetime.now(tz=timezone.utc) - timedelta(days=self.max_age_days)
        paginator = iam_client.get_paginator("list_users")

        for page in paginator.paginate():
            for user in page["Users"]:
                keys = iam_client.list_access_keys(UserName=user["UserName"])
                for key in keys["AccessKeyMetadata"]:
                    if key["Status"] != "Active":
                        continue  # inactive keys are already neutered
                    last_used = iam_client.get_access_key_last_used(
                        AccessKeyId=key["AccessKeyId"]
                    )["AccessKeyLastUsed"].get("LastUsedDate")
                    if last_used is None or last_used < cutoff:
                        yield Finding(
                            check_id="IAM-001",
                            severity=Severity.HIGH,
                            resource=user["Arn"],
                            message=f"Access key {key['AccessKeyId']} unused for >{self.max_age_days} days",
                            remediation="Deactivate or delete the key in IAM console or via aws iam delete-access-key",
                        )

cli.py — entry point and wiring

Parses arguments with argparse, creates a boto3 IAM client using the named profile (or the default credential chain if none is given), runs every registered check, and passes findings to the chosen reporter. Exit code is 0 for clean, 1 for any findings — this is the CI gate hook. 

def main() -> None:
    args = parse_args()
    session = boto3.Session(profile_name=args.profile)
    iam = session.client("iam")

    checks: list[Check] = [
        UnusedAccessKeysCheck(max_age_days=args.max_key_age_days),
    ]

    findings: list[Finding] = []
    for check in checks:
        findings.extend(check.run(iam))

    reporter = JsonReporter() if args.format == "json" else TerminalReporter()
    reporter.report(findings)

    # Non-zero exit = CI pipeline fails on findings
    raise SystemExit(1 if findings else 0)

tests/ — moto-backed unit tests

Tests use the @mock_aws decorator from moto, which intercepts all boto3 calls and routes them to an in-memory IAM mock. This means no AWS account or credentials are needed to run the test suite — critical for CI. 

from moto import mock_aws
import boto3, pytest
from iam_auditor.checks.unused_access_keys import UnusedAccessKeysCheck

@mock_aws
def test_flags_stale_key() -> None:
    iam = boto3.client("iam", region_name="us-east-1")
    iam.create_user(UserName="alice")
    iam.create_access_key(UserName="alice")  # key is Active, never used

    check = UnusedAccessKeysCheck(max_age_days=90)
    findings = list(check.run(iam))

    assert len(findings) == 1
    assert findings[0].check_id == "IAM-001"
    assert findings[0].severity.value == "HIGH"

Required IAM Permissions

The runtime principal only needs read-only access. The minimum least-privilege policy — no * on actions, no write permissions: 

{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": [
      "iam:ListUsers",
      "iam:ListAccessKeys",
      "iam:GetAccessKeyLastUsed"
    ],
    "Resource": "*"  // IAM list/get operations require * resource
  }]
}

The AWS-managed SecurityAudit or ReadOnlyAccess policies also satisfy this requirement.

Replicate It Yourself

  1. Scaffold with hatchling. Create pyproject.toml with [build-system] using hatchling and a [project.scripts] entry point. This gives you a proper pip install -e . CLI with no setup.py. Reference: Hatch build config docs.
  2. Define your data contract first. Write models.py with a Finding dataclass and Severity enum before writing any check. Every check returns these types — a stable contract means you can change reporters without touching checks.
  3. Write the Check ABC. One abstract method: run(iam_client) -> Iterator[Finding]. Use Iterator (not list) so checks stream findings without buffering — important when auditing large accounts with thousands of users. Reference: Python ABC docs.
  4. Use paginators, not plain API calls. IAM APIs are paginated. Always use iam_client.get_paginator("list_users") instead of iam_client.list_users() — a plain call silently truncates at 100 results. Reference: boto3 paginators.
  5. Test with moto, not a real account. Add moto[iam] to dev dependencies and decorate tests with @mock_aws. Your CI pipeline can run the full test suite without AWS credentials. Reference: moto IAM docs.
  6. Set a meaningful exit code. raise SystemExit(1 if findings else 0) in main(). This is the CI gate — any pipeline that runs iam-auditor as a step will fail the build when findings exist.
