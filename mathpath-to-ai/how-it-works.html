MathPath to AI — How It's Built

A free, structured math curriculum — from algebra to the math behind modern AI, taught in dependency order.

Overview

MathPath to AI answers a specific frustration: most "math for machine learning" resources either assume you already have the prerequisites or scatter topics in an order that doesn't build. This curriculum lays the whole path out as one sequence — algebra foundations, geometry and trigonometry, precalculus, calculus, linear algebra, probability and statistics, and finally the optimization and AI math that sit on top of all of it. Each stage is there because the next stage needs it: linear algebra is the language neural networks are written in, calculus is what makes gradient descent work, and probability is how models express uncertainty. The site is free, self-paced, and static — no accounts, no backend, nothing to run.

Tech Stack

TypeScript Next.js HTML CSS
  • TypeScript — the curriculum and lesson content are typed data, so a malformed lesson fails at build time instead of on the page
  • Next.js — builds the site and statically exports it: every route pre-rendered to plain HTML that any static host can serve
  • HTML / CSS — the exported pages; fast by construction, since there is no server and no runtime data fetching

How Each Part Works

The curriculum is a dependency graph

The path is stored as ordered data: stages contain units, units contain lessons, and each stage declares what it assumes from the stages before it. Rendering is the easy part — the real design work is the ordering. A topic appears only after everything it depends on, which is what makes the path usable for self-study without an instructor sequencing it for you.

Static export, two doors

The source lives in its own repository (mathpath-to-ai) as a Next.js project. The build statically exports the whole curriculum to plain HTML/CSS/JS, and that export is what this hub folder hosts — so the curriculum is reachable both as a standalone project and as part of the App Hub, with no server behind either door. Updating it means editing the source, re-exporting, and replacing the export — the two copies can't quietly drift apart because one is generated from the other.

Why static matters here

A curriculum is read far more than it is updated. Pre-rendering every page at build time means instant loads, free hosting on GitHub Pages, and nothing to patch or keep alive. The trade-off — no per-user progress accounts — is deliberate: the path is a reference you walk, not a service you sign up for.

Replicate It Yourself

  1. Map the prerequisites first. List the topics your subject needs, then draw the dependency arrows. The order of your curriculum is just a topological sort of that graph — everything else is presentation.
  2. Store the curriculum as typed data. Stages, units, and lessons as data structures — not hard-coded pages — so reordering a stage is a data edit, not a rewrite.
  3. Build with Next.js and export statically. Pre-render every route at build time; host the output anywhere that serves files. Reference: Next.js static exports.
  4. Deploy to GitHub Pages. Push to main, go to repo Settings → Pages → Source: Deploy from branch → main / (root). Reference: GitHub Pages docs.
