Lambda: Ship a Function, Hardened

Three tracks, same lab. We deploy a Python 3.12 function on ARM64 with a tightly scoped execution role, log retention pinned, X-Ray on, reserved concurrency capped — and prove it works with a clean test invocation.

What's in this tutorial

  1. Prerequisites & safety net
  2. What we'll build
  3. Track A — Console (click-by-click)
  4. Track B — AWS CLI v2
  5. Track C — Terraform
  6. Verify the function (invoke, logs, X-Ray)
  7. Cleanup — read this first
  8. Senior-engineer takeaways

01 Prerequisites & safety net

You'll need

  • An AWS account (everything in this tutorial is free-tier eligible).
  • An IAM user or Identity Center role with permission to create IAM roles + policies, Lambda functions, and CloudWatch log groups. Don't use the root account.
  • AWS CLI v2 installed (aws --version should print 2.x).
  • Terraform 1.7+ for Track C.
  • zip on your shell PATH (preinstalled on macOS / most Linux distros).

Configure a named CLI profile (one-time setup)

Don't dump credentials into env vars; use named profiles in ~/.aws/credentials. Replace eddie-lab with whatever you want to call this profile.

aws configure --profile eddie-lab
# AWS Access Key ID [None]: AKIA...
# AWS Secret Access Key [None]: ...
# Default region name [None]: us-east-1
# Default output format [None]: json

# Verify and capture your account ID for later
aws sts get-caller-identity --profile eddie-lab
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text --profile eddie-lab)
echo "Account: $ACCOUNT_ID"

Every CLI command in this tutorial uses --profile eddie-lab --region us-east-1. Adjust to your profile/region.

⚠️ A note about the principle of least privilege

The temptation is always to attach AWSLambdaBasicExecutionRole (which grants logs:CreateLogGroup + logs:CreateLogStream + logs:PutLogEvents on *), get the function working, and "tighten it later." We're going to write a scoped logs policy that targets only this function's log group. That friction is the muscle memory you'll bring to every production Lambda you ever ship.

02 What we'll build

One Python 3.12 Lambda named lambda-tutorial-fn, deployed with every production-relevant knob set correctly:

  • ARM64 (Graviton) architecture — ~20% cheaper than x86 at equivalent performance.
  • Memory 256 MB · timeout 10s · reserved concurrency 5 — bounded blast radius.
  • Custom execution role with a scoped policy granting only logs:CreateLogStream + logs:PutLogEvents on this function's own log group. No AWSLambdaBasicExecutionRole.
  • Pre-created CloudWatch log group /aws/lambda/lambda-tutorial-fn with 14-day retention (the default is "never expire" — that's a bill).
  • X-Ray active tracing on, so the next time you debug a slow invocation you have the data.
  • Versioning + a prod alias — you call the alias, not $LATEST.
  • No Function URL, no public exposure. We invoke directly to keep the lab self-contained.
  • Tagged Project=lambda-tutorial for cleanup.
Why this lab

"Ship one Lambda the right way" is the AWS Security Specialty exam in microcosm. Every knob you set here — scoped role, retention, concurrency, tracing — is a question on SCS-C02 and a finding category on every AWS audit you'll ever read. The pattern scales: a fleet of 400 Lambdas hardened this way is the difference between "we passed FedRAMP" and "we have to redo six months of work."

The function itself is intentionally trivial — an event-echoing handler:

def handler(event, context):
    return {
        "statusCode": 200,
        "body": {
            "message": "hello from a hardened Lambda",
            "received_event": event,
        },
    }

The point is the deployment hardening, not the code. The same hardening pattern applies to a 200-line handler doing real work.

Track A Console — click-by-click

Best for the first time, when you want to see every page that hides a setting you'll later automate.

  1. Sign in at console.aws.amazon.com as your IAM user (not root). Pick region US East (N. Virginia) us-east-1 top right.
  2. Pre-create the log group with retention. Go to CloudWatch → Log groups → Create log group.
    • Name: /aws/lambda/lambda-tutorial-fn (the exact name Lambda would auto-create — we want to own it ourselves so retention is set from minute one).
    • Retention setting: 2 weeks (14 days). Default is Never expire; that's a slow-moving bill.
    • Create.
  3. Create the scoped logs policy. Go to IAM → Policies → Create policy. Switch to the JSON tab and paste (replace <ACCOUNT_ID> with your account number): 
    {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ScopedLogs",
      "Effect": "Allow",
      "Action": [
        "logs:CreateLogStream",
        "logs:PutLogEvents"
      ],
      "Resource": "arn:aws:logs:us-east-1:<ACCOUNT_ID>:log-group:/aws/lambda/lambda-tutorial-fn:*"
    }
  ]
}
    Name it lambda-tutorial-scoped-logs. Create policy.
  4. Create the execution role. Go to IAM → Roles → Create role.
    • Trusted entity type: AWS service → use case Lambda.
    • Permissions: attach only lambda-tutorial-scoped-logs. Skip AWSLambdaBasicExecutionRole — we deliberately don't want the wildcard.
    • Name: lambda-tutorial-role.
    • Create role.
  5. Create the function. Go to Lambda → Create function → Author from scratch.
    • Function name: lambda-tutorial-fn.
    • Runtime: Python 3.12.
    • Architecture: arm64.
    • Permissions: Use an existing role → lambda-tutorial-role.
    • Create function.
  6. Replace the placeholder code. On the function's Code tab, paste: 
    def handler(event, context):
    return {
        "statusCode": 200,
        "body": {
            "message": "hello from a hardened Lambda",
            "received_event": event,
        },
    }
    Click Deploy. Then in Runtime settings → Edit, change the Handler to lambda_function.handler (Console saves the file as lambda_function.py by default, so the handler path is file.function).
  7. Set the production knobs. Open Configuration tab.
    • General configuration → Edit: Memory 256 MB, Timeout 10 sec. Save.
    • Concurrency and recursion detection → Edit: Reserved concurrency 5. Save.
    • Monitoring and operations tools → Edit: turn on Active tracing (X-Ray). Save.
    • Tags → Add tag: Key Project, Value lambda-tutorial. Save.
  8. Publish version 1 and the prod alias.
    • Top-right Actions → Publish new version. Description v1 hardened baseline. Publish.
    • Aliases tab → Create alias. Name prod, Version 1. Create.
  9. Test invocation. Go to the Test tab. Create a new test event named hello with body: 
    { "name": "Eddie", "stage": "lab" }
    Save and Test. Expect a 200 with the echoed event in body.received_event.

Skip ahead to Verify for the cross-track checks (logs + X-Ray trace).

Track B AWS CLI v2

Same lab, all from your terminal. Worth doing once — you learn what every Console button is actually calling.

1. Set vars and pre-create the log group

FN=lambda-tutorial-fn
ROLE=lambda-tutorial-role
POLICY=lambda-tutorial-scoped-logs
LOG_GROUP="/aws/lambda/$FN"
PROFILE=eddie-lab
REGION=us-east-1
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text --profile "$PROFILE")

# Pre-create the log group with 14-day retention
aws logs create-log-group \
  --log-group-name "$LOG_GROUP" \
  --region "$REGION" --profile "$PROFILE"

aws logs put-retention-policy \
  --log-group-name "$LOG_GROUP" \
  --retention-in-days 14 \
  --region "$REGION" --profile "$PROFILE"

2. Write the trust + permission policies

cat > /tmp/lambda-trust.json <<'EOF'
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": { "Service": "lambda.amazonaws.com" },
    "Action": "sts:AssumeRole"
  }]
}
EOF

cat > /tmp/lambda-scoped-logs.json <<EOF
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "ScopedLogs",
    "Effect": "Allow",
    "Action": [
      "logs:CreateLogStream",
      "logs:PutLogEvents"
    ],
    "Resource": "arn:aws:logs:${REGION}:${ACCOUNT_ID}:log-group:${LOG_GROUP}:*"
  }]
}
EOF

3. Create the role + scoped policy + attach

POLICY_ARN=$(aws iam create-policy \
  --policy-name "$POLICY" \
  --policy-document file:///tmp/lambda-scoped-logs.json \
  --query 'Policy.Arn' --output text \
  --profile "$PROFILE")

aws iam create-role \
  --role-name "$ROLE" \
  --assume-role-policy-document file:///tmp/lambda-trust.json \
  --tags Key=Project,Value=lambda-tutorial \
  --profile "$PROFILE"

aws iam attach-role-policy \
  --role-name "$ROLE" \
  --policy-arn "$POLICY_ARN" \
  --profile "$PROFILE"

ROLE_ARN=$(aws iam get-role --role-name "$ROLE" \
  --query 'Role.Arn' --output text --profile "$PROFILE")
echo "Role ARN: $ROLE_ARN"

4. Write and zip the function code

WORKDIR=$(mktemp -d)
cat > "$WORKDIR/lambda_function.py" <<'EOF'
def handler(event, context):
    return {
        "statusCode": 200,
        "body": {
            "message": "hello from a hardened Lambda",
            "received_event": event,
        },
    }
EOF

(cd "$WORKDIR" && zip -q function.zip lambda_function.py)
ls -lh "$WORKDIR/function.zip"

5. Create the function with all the knobs

# IAM role propagation can take a few seconds the first time
sleep 8

aws lambda create-function \
  --function-name "$FN" \
  --runtime python3.12 \
  --architectures arm64 \
  --handler lambda_function.handler \
  --memory-size 256 \
  --timeout 10 \
  --role "$ROLE_ARN" \
  --zip-file "fileb://$WORKDIR/function.zip" \
  --tracing-config Mode=Active \
  --tags "Project=lambda-tutorial" \
  --region "$REGION" --profile "$PROFILE"

# Cap concurrency so a runaway loop can't fan out beyond 5
aws lambda put-function-concurrency \
  --function-name "$FN" \
  --reserved-concurrent-executions 5 \
  --region "$REGION" --profile "$PROFILE"

6. Publish v1 + alias prod

VERSION=$(aws lambda publish-version \
  --function-name "$FN" \
  --description "v1 hardened baseline" \
  --query Version --output text \
  --region "$REGION" --profile "$PROFILE")

aws lambda create-alias \
  --function-name "$FN" \
  --name prod \
  --function-version "$VERSION" \
  --description "production alias" \
  --region "$REGION" --profile "$PROFILE"

7. Test invocation through the alias

# Invoke the alias (not $LATEST) — this is what production callers do
aws lambda invoke \
  --function-name "${FN}:prod" \
  --payload '{"name":"Eddie","stage":"lab"}' \
  --cli-binary-format raw-in-base64-out \
  --region "$REGION" --profile "$PROFILE" \
  /tmp/lambda-out.json

cat /tmp/lambda-out.json

Now skip to Verify for the logs + X-Ray check.

Track C Terraform

The production track. Idempotent, code-reviewable, destroy-safe.

1. Working directory and code

mkdir -p ~/labs/lambda-tutorial && cd ~/labs/lambda-tutorial

# Function source lives next to main.tf
cat > lambda_function.py <<'EOF'
def handler(event, context):
    return {
        "statusCode": 200,
        "body": {
            "message": "hello from a hardened Lambda",
            "received_event": event,
        },
    }
EOF

Save this as main.tf:

terraform {
  required_version = ">= 1.7"
  required_providers {
    aws     = { source = "hashicorp/aws",     version = "~> 5.0" }
    archive = { source = "hashicorp/archive", version = "~> 2.4" }
  }
}

provider "aws" {
  region  = "us-east-1"
  profile = "eddie-lab"

  default_tags {
    tags = {
      Project   = "lambda-tutorial"
      ManagedBy = "terraform"
    }
  }
}

locals {
  fn_name = "lambda-tutorial-fn"
}

# Pre-create the log group so retention is set from minute one
resource "aws_cloudwatch_log_group" "fn" {
  name              = "/aws/lambda/${local.fn_name}"
  retention_in_days = 14
}

# Trust policy: only Lambda may assume this role
data "aws_iam_policy_document" "lambda_trust" {
  statement {
    effect  = "Allow"
    actions = ["sts:AssumeRole"]
    principals {
      type        = "Service"
      identifiers = ["lambda.amazonaws.com"]
    }
  }
}

# Permission policy: scoped to this function's log group only
data "aws_iam_policy_document" "scoped_logs" {
  statement {
    sid       = "ScopedLogs"
    effect    = "Allow"
    actions   = ["logs:CreateLogStream", "logs:PutLogEvents"]
    resources = ["${aws_cloudwatch_log_group.fn.arn}:*"]
  }
}

resource "aws_iam_role" "lambda" {
  name               = "lambda-tutorial-role"
  assume_role_policy = data.aws_iam_policy_document.lambda_trust.json
}

resource "aws_iam_role_policy" "scoped_logs" {
  name   = "scoped-logs"
  role   = aws_iam_role.lambda.id
  policy = data.aws_iam_policy_document.scoped_logs.json
}

# Zip the function source on apply
data "archive_file" "fn" {
  type        = "zip"
  source_file = "${path.module}/lambda_function.py"
  output_path = "${path.module}/function.zip"
}

resource "aws_lambda_function" "fn" {
  function_name                  = local.fn_name
  role                           = aws_iam_role.lambda.arn
  runtime                        = "python3.12"
  architectures                  = ["arm64"]
  handler                        = "lambda_function.handler"
  filename                       = data.archive_file.fn.output_path
  source_code_hash               = data.archive_file.fn.output_base64sha256
  memory_size                    = 256
  timeout                        = 10
  reserved_concurrent_executions = 5    # cap blast radius
  publish                        = true # immutable version on every code change

  tracing_config {
    mode = "Active"
  }

  # Make sure the log group exists before the function tries to write to it
  depends_on = [
    aws_cloudwatch_log_group.fn,
    aws_iam_role_policy.scoped_logs,
  ]
}

resource "aws_lambda_alias" "prod" {
  name             = "prod"
  function_name    = aws_lambda_function.fn.function_name
  function_version = aws_lambda_function.fn.version
  description      = "production alias"
}

output "function_name" { value = aws_lambda_function.fn.function_name }
output "function_arn"  { value = aws_lambda_function.fn.arn }
output "alias_arn"     { value = aws_lambda_alias.prod.arn }
output "log_group"     { value = aws_cloudwatch_log_group.fn.name }

2. Init, plan, apply

terraform init
terraform plan      # READ THIS. Always read the plan before applying.
terraform apply     # type 'yes' to confirm

Outputs print the function name, ARN, alias ARN, and log group. Now go to Verify.

Why this is the production track

Idempotent (apply twice = same result), code-reviewable (your teammate sees the diff), and reversible in one command (terraform destroy). The CLI track is great for learning what's underneath; Terraform is what you'd actually use at work.

06 Verify the function (invoke, logs, X-Ray)

Function exists. Role looks tight. Prove the whole pipeline works end-to-end before you forget about it.

Invoke through the alias and read the response

FN=lambda-tutorial-fn
PROFILE=eddie-lab
REGION=us-east-1

aws lambda invoke \
  --function-name "${FN}:prod" \
  --payload '{"name":"Eddie","stage":"verify"}' \
  --cli-binary-format raw-in-base64-out \
  --region "$REGION" --profile "$PROFILE" \
  /tmp/lambda-out.json

cat /tmp/lambda-out.json
# Expect statusCode 200 and the echoed event under body.received_event

Tail the CloudWatch log group

aws logs tail "/aws/lambda/$FN" \
  --since 10m --follow \
  --region "$REGION" --profile "$PROFILE"
# You'll see START / END / REPORT lines per invocation. Ctrl-C to exit.

Confirm retention is actually set (the easy thing to forget)

aws logs describe-log-groups \
  --log-group-name-prefix "/aws/lambda/$FN" \
  --query 'logGroups[0].[logGroupName,retentionInDays]' \
  --output table \
  --region "$REGION" --profile "$PROFILE"
# retentionInDays should read 14, not None.

Pull an X-Ray trace

Active tracing means each invocation produces a trace segment. Find a recent one:

aws xray get-trace-summaries \
  --start-time $(date -u -v-10M +%s 2>/dev/null || date -u -d '10 min ago' +%s) \
  --end-time   $(date -u +%s) \
  --filter-expression "service(\"$FN\")" \
  --query 'TraceSummaries[0].Id' \
  --output text \
  --region "$REGION" --profile "$PROFILE"
# Take the trace ID and look it up in the X-Ray Console for the segment timeline.
The audit pattern

Invoke proves the role is sufficient (function ran). Logs prove retention works (and that you can find them in 14 days but not in 14 years of unbounded billing). X-Ray proves you'll have the data when an invocation slows down. Three checks, one minute — this is the baseline every Lambda review starts with.

07 Cleanup — read this first

Why this matters

Idle Lambdas don't cost much — but a forgotten function with broad permissions, an unbounded log group, and an open Function URL is a slow leak. Delete labs when you're done. Future-you will not remember which one of 12 tutorial-* functions was the safe one.

Track C (Terraform) — easiest

cd ~/labs/lambda-tutorial
terraform destroy   # type 'yes' — wipes everything we created

Track B (CLI) — manual

FN=lambda-tutorial-fn
ROLE=lambda-tutorial-role
POLICY=lambda-tutorial-scoped-logs
PROFILE=eddie-lab
REGION=us-east-1

# Delete alias, then function (alias must go first)
aws lambda delete-alias    --function-name "$FN" --name prod      --profile "$PROFILE" --region "$REGION" || true
aws lambda delete-function --function-name "$FN" --profile "$PROFILE" --region "$REGION"

# Detach + delete the policy, then delete the role
POLICY_ARN=$(aws iam list-policies --scope Local \
  --query "Policies[?PolicyName=='$POLICY'].Arn" --output text --profile "$PROFILE")
aws iam detach-role-policy --role-name "$ROLE" --policy-arn "$POLICY_ARN" --profile "$PROFILE"
aws iam delete-policy      --policy-arn "$POLICY_ARN" --profile "$PROFILE"
aws iam delete-role        --role-name "$ROLE" --profile "$PROFILE"

# Delete the log group last (so the previous deletes still log if they need to)
aws logs delete-log-group --log-group-name "/aws/lambda/$FN" --profile "$PROFILE" --region "$REGION"

Track A (Console)

  1. Lambda → Functions → lambda-tutorial-fn → Aliases → delete prod, then delete the function.
  2. IAM → Roles → delete lambda-tutorial-role. The Console offers to detach policies for you.
  3. IAM → Policies → delete lambda-tutorial-scoped-logs.
  4. CloudWatch → Log groups → delete /aws/lambda/lambda-tutorial-fn.

Verify nothing is left

aws lambda list-functions \
  --query "Functions[?contains(FunctionName, 'lambda-tutorial')].FunctionName" \
  --profile eddie-lab --region us-east-1
# (empty output = nothing left)

aws iam list-roles \
  --query "Roles[?contains(RoleName, 'lambda-tutorial')].RoleName" \
  --profile eddie-lab
# (empty output = nothing left)

aws logs describe-log-groups \
  --log-group-name-prefix "/aws/lambda/lambda-tutorial" \
  --query 'logGroups[].logGroupName' \
  --profile eddie-lab --region us-east-1
# (empty output = nothing left)

08 Senior-engineer takeaways

What this exercise drilled into you

  • The execution role is the security model. A function's blast radius is its role's permissions, no more and no less. Scoped policies beat AWSLambdaBasicExecutionRole every time.
  • Pre-create the log group. If Lambda creates it on first invocation, retention defaults to Never expire. Owning the resource yourself means owning the retention from minute one.
  • Reserved concurrency is a circuit breaker. Default unbounded concurrency is fine when traffic is predictable. It's a four-figure surprise the first time it isn't.
  • Versions + aliases beat $LATEST. Production callers point at prod; rollbacks are a one-line alias change. Don't ship anything important against $LATEST.
  • X-Ray is free until you turn it on for everything. Active tracing on a single hardened function pays for itself the first time you have to debug a 9-second cold start.

Where to take it next

  • Add a Function URL with AWS_IAM auth, then practice invoking via SigV4 from a separate IAM principal.
  • Hook the function to an EventBridge rule (cron) and watch logs accumulate over a day. Confirm retention truncates after 14 days.
  • Add a code-signing config with AWS Signer; reject unsigned deployments.
  • Move the function to a container image (ECR-hosted) with the same hardening — understand the trade-offs vs zip.
  • Read up on OWASP Serverless Top 10 and walk through your function against each item.
  • Take the AWS Security Specialty (SCS-C02) exam — the serverless-security domain is essentially this lab generalized.

Costs at a glance

  • Lambda invocations: 1M free per month, then $0.20 per million. The lab uses ~5 invocations.
  • Lambda compute: 400,000 GB-seconds free per month, then $0.0000133/GB-s on ARM64. Lab uses ~0.5 GB-s.
  • CloudWatch Logs: free tier covers 5 GB/month ingested + 5 GB stored. The lab generates kilobytes.
  • X-Ray: 100k traces/month free, then $5/million. Lab uses ~5.
  • IAM users, roles, policies: free.

Pricing reference: aws.amazon.com/lambda/pricing. Verify before quoting professionally — AWS adjusts pricing periodically.
