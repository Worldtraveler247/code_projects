AWS in Practice — How It's Built

A 10-service static reference site: honest docs, runnable tutorials, three tracks side-by-side — Console, CLI, and Terraform.

Overview

AWS in Practice is a static educational site hosted on GitHub Pages. Each of the 10 service pages follows the same layout: a plain-English overview of what the service does and who uses it, followed by a hands-on tutorial written in three parallel tracks so you can compare how the same operation looks in the AWS Console, the CLI, and Terraform. There is no backend, no build step — every page is hand-authored HTML/CSS/JS loaded directly by the browser. The goal is to give early-career cloud engineers a trustworthy, security-first reference that does not hide the tradeoffs.

Tech Stack

HTML CSS JavaScript AWS Terraform GitHub Pages
  • HTML — every page is a standalone document; semantic structure (nav, main, section, figure) makes the content outline clear without JavaScript.
  • CSS — a single shared stylesheet (aws-hub.css) drives the dark-navy theme, AWS-orange accents, service card grid, code blocks, and callout boxes across the whole series.
  • JavaScript — nav.js handles three tasks: highlighting the active service in the top nav, attaching copy-to-clipboard buttons on every code block, and a scroll-reveal effect via IntersectionObserver.
  • AWS — all CLI commands, policy JSON, and console steps come from real AWS documentation and are written to work against free-tier accounts.
  • Terraform — HCL blocks in the tutorial pages reference the official Terraform AWS provider registry, so readers can paste them directly into a working configuration.
  • GitHub Pages — zero-config static hosting; a push to main deploys in under a minute with no build pipeline required.

How Each Part Works

aws-series/index.html — Hub landing page

The hub is a single HTML file containing a 10-card service grid. Each card is an anchor element linking to the matching service subdirectory, with an icon, title, one-sentence description, and colored category tags. No JavaScript is needed to navigate — the browser follows standard links. The "How to use this series" section and prerequisites checklist live on this same page.

ec2/index.html — Service overview page

Each service has an overview page and a separate tutorial page. The overview explains the service in plain English: what it is, who actually uses it, and honest tradeoffs versus alternatives. A small inline SVG serves as hero art — no external images to load. The page shares the same top nav as the hub via an identical HTML snippet and is styled identically by aws-hub.css.

iam/tutorial.html — Three-track tutorial layout

Tutorial pages use three labeled sections — Track A (Console), Track B (CLI), Track C (Terraform) — separated by visually distinct pill badges. Each track is a standard HTML section with an anchor ID so readers can link directly to the track they need. Code samples sit inside .code-block > pre elements; nav.js attaches a Copy button to each one at runtime. The scroll-reveal uses IntersectionObserver: .reveal elements get a visible class when they enter the viewport, triggering a CSS fade-in.

// nav.js — copy-to-clipboard attached to every .code-block pre
document.querySelectorAll('.code-block').forEach((block) => {
  const pre = block.querySelector('pre');
  if (!pre) return;
  const btn = document.createElement('button');
  btn.className = 'copy-btn';
  btn.textContent = 'Copy';
  btn.addEventListener('click', async () => {
    try {
      await navigator.clipboard.writeText(pre.innerText);
      btn.textContent = 'Copied';
      btn.classList.add('copied');
      setTimeout(() => {
        btn.textContent = 'Copy';
        btn.classList.remove('copied');
      }, 1600);
    } catch {
      // Fallback: select text so the user can copy manually
      const range = document.createRange();
      range.selectNodeContents(pre);
      window.getSelection().removeAllRanges();
      window.getSelection().addRange(range);
      btn.textContent = 'Select all';
    }
  });
  block.appendChild(btn);
});

// Scroll-reveal via IntersectionObserver
const io = new IntersectionObserver(
  (entries) => entries.forEach((e) => {
    if (e.isIntersecting) {
      e.target.classList.add('visible');
      io.unobserve(e.target);
    }
  }),
  { threshold: 0.12 }
);
document.querySelectorAll('.reveal').forEach((el) => io.observe(el));

css/aws-hub.css — Shared stylesheet

One CSS file drives the entire series. It defines CSS custom properties for the AWS-orange brand color, navy backgrounds, and border tokens, then styles the nav, hero section, service card grid, CSS counter-increment step numbers, track-pill badges, callout boxes, and code blocks. Every page in the series references this file at ../css/aws-hub.css (or css/aws-hub.css from the hub root).

js/nav.js — Shared client-side helper

A 65-line IIFE loaded by every page. It reads document.body.dataset.svc (e.g., data-svc="ec2" set on <body>) and adds an active class to the matching nav link — giving each service its own highlighted nav entry without any framework. Copy-to-clipboard and scroll-reveal run on the same load, keeping the interaction budget to one script file per page.

Replicate It Yourself

  1. Create a GitHub repo and enable Pages from the main branch. No build step — Pages serves HTML files directly at https://<user>.github.io/<repo>/.
  2. Create a shared css/theme.css with CSS custom properties for your brand colors and a js/nav.js for shared interactivity. Reference them from every page using relative paths.
  3. Build the hub index.html as a grid of anchor cards — one per service — each linking to service-name/index.html.
  4. For each service, create an overview page and a tutorial page. Set data-svc="service-name" on <body> so the shared nav script can highlight the active entry.
  5. Write tutorial content in three parallel sections (Console, CLI, Terraform). Source CLI flags from aws help <command> and Terraform blocks from registry.terraform.io.
  6. Wrap code samples in <div class="code-block"><pre>...</pre></div>. The shared nav.js will auto-attach a Copy button to every one on page load.
  7. Push to main. GitHub Pages deploys within ~60 seconds. Verify with curl -I https://<user>.github.io/<repo>/aws-series/.
