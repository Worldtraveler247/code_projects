Async 3D Chess — How It's Built

Correspondence chess for busy friends: private game links, server-enforced seats and turns, WhatsApp nudges, and a 3D or 2D board.

Overview

Async 3D Chess is built for friends who can't sit through a ten-minute game. One player starts a game and sends a private invite link; the first person to open it claims the Black seat. From then on, each player moves whenever they have a minute — the board syncs in real time when both are online and waits patiently when they aren't. After moving, a player can nudge their opponent on WhatsApp with one tap, and the browser tab title shows ● Your move whenever it's your turn.

The board renders as a Three.js scene with Staunton-style pieces, or as a flat 2D board for small screens and quick moves. chess.js validates moves in the browser; Firebase Realtime Database stores each game, and Firebase security rules enforce who may sit where and whose turn it is on Google's servers, so a modified client cannot move out of turn, steal a seat, or overwrite the opponent's name. Without a game link, the page is a local pass-and-play board that never touches the database.

How Each Part Works

Data model — one node per game

Every game lives at games/{id}. The ID is 128 bits from the browser's cryptographic random generator, encoded as 22 base64url characters. That ID is the invite: knowing it lets you watch or claim an empty seat, and it can't be guessed. (Firebase push IDs were avoided because their first 8 characters are a timestamp.) The rules deny reads on games/ itself, so nobody can list other people's games. 

games/
  Xk3…22 chars…/
    players:   { w: "<White's auth uid>", b: "<Black's auth uid>" }   // claim-once
    state:     { fen, turn: "w" | "b", lastMove: "e4", updatedAt }   // side to move only
    names:     { w: "Alice", b: "Bob" }                              // own seat only
    comments:  { w: "gl hf", b: "…" }                                // own seat only
    createdAt: <server time>

// 128-bit unguessable ID — the invite link is the capability
function newGameId() {
    const bytes = crypto.getRandomValues(new Uint8Array(16));
    return btoa(String.fromCharCode(...bytes))
        .replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');
}

database.rules.json — the real security boundary

Anything in the browser can be edited by the person using it, so the client's "is it my turn?" check is a convenience, not a control. The rules run on Firebase's servers and decide every write. The key rule: a write to state is allowed only if the caller's user ID matches the seat whose turn it currently is. The write must also hand the turn to the other side, keep the FEN's side-to-move consistent with turn, and use the server's clock. Seats can be written once and never reassigned. 

"state": {
  // Only the player whose turn it is may write the next position
  ".write": "auth != null && data.exists() &&
             root.child('games/' + $gameId + '/players/' + data.child('turn').val()).val() === auth.uid",
  // ...and the turn must flip, FEN must agree with it, and time is server time
  ".validate": "… newData.child('turn').val() !== data.child('turn').val() …",
  "updatedAt": { ".validate": "newData.val() === now" },
  "$other":    { ".validate": false }          // no surprise fields
},
"players": {
  "b": {
    // first come, first served — and White can't also take Black
    ".write": "auth != null && !data.exists() && … players/w !== auth.uid"
  }
}

Known limit: the rules language can't run chess.js, so the server checks that a position is well-formed and that turns alternate — not that the move was legal. A player who edits their client could submit an illegal position on their own turn. For games between friends that's an accepted risk. The planned fix is a Cloud Function that replays each move with chess.js on the server.

rules-test/ — attacking the rules before shipping them

@firebase/rules-unit-testing runs the rules in the local Database Emulator and exercises them as different users: the creator, the friend, and an outsider ("mallory"). The 32 tests cover moving out of turn, moving twice, stealing or pre-assigning seats, hijacking a game mid-play by rewriting the whole node, forged timestamps, malformed FENs, oversized names, extra fields, enumerating games, and writes to the retired current_match node. The suite was mutation-tested: deliberately weakening a rule must turn at least one test red, which exposed and fixed a test that was passing by coincidence. 

test('cannot move out of turn', async () => {
    await seatedGame();                                  // alice = White, bob = Black
    await assertFails(set(g('bob', '/state'), move(AFTER_E4, 'b', 'e4')));
});

test('cannot hijack a game mid-play by rewriting the whole node', async () => {
    await seatedGame();
    await assertSucceeds(set(g('alice', '/state'), move(AFTER_E4, 'b', 'e4')));
    await assertFails(set(g('mallory'), newGame('mallory')));
});

app.js — joining, syncing, and committing moves

On load the page signs in anonymously. If the URL has ?g=<id>, it subscribes to that game with onValue, which fires once with the current state and again on every change. Each snapshot works out the viewer's seat (White, Black, or spectator), loads the FEN into chess.js if it changed, and redraws whichever board is showing. A move is applied locally first for instant feedback, then written to state. If the server rejects it, the board snaps back to the last confirmed position. 

function onGameSnapshot(snap) {
    const data = snap.val();
    remote = data;
    mySeat = data.players.w === uid ? 'w' : data.players.b === uid ? 'b' : null;
    if (data.state.fen !== game.fen()) {
        game.load(data.state.fen);
        sync3DWithEngine();           // rebuilds pieces, status, both boards
    }
    renderOnlinePanel();              // join / invite / nudge buttons
}

async function commitMove(move) {
    const before = remote?.state?.fen;
    try {
        await set(ref(db, `games/${gameId}/state`), {
            fen: game.fen(), turn: game.turn(), lastMove: move.san,
            updatedAt: serverTimestamp(),           // server clock, enforced by rules
        });
    } catch (e) {
        showNotice('Move rejected by the server — board restored.');
        if (before) { game.load(before); sync3DWithEngine(); }
    }
}

app.js — WhatsApp nudges without collecting phone numbers

After you move, a Nudge on WhatsApp button appears. It opens a wa.me share link that has the message but no phone number, so WhatsApp shows its own contact picker and the friend gets the nudge from your number. This needs no server and no WhatsApp Business account, costs nothing per message, and keeps phone numbers out of the app entirely. Automated sending through the WhatsApp Business Platform was considered and rejected for a friends' game: it needs Meta business verification and pre-approved templates, charges per message, and would make the app responsible for storing phone numbers. 

function whatsappShare(text) {
    // No phone number in the URL → WhatsApp's own contact picker
    window.open('https://wa.me/?text=' + encodeURIComponent(text), '_blank', 'noopener');
}

function nudgeOpponent() {
    whatsappShare(`♟ Your move in our chess game, ${playerName(opponentSeat())}. ${gameUrl(gameId)}`);
}

app.js — 2D view and click-to-move

The 2D board is a grid of 64 buttons generated from the same chess.js state as the 3D scene, and its clicks go through the same handleSquareClick(). The two views can't disagree because there is only one copy of the game. In 3D, a Raycaster turns a click into a ray, and the first board tile it hits gives the square name stored in userData.square. While 2D is active, the WebGL render loop and touch raycasting are paused. 

function pickSquare(clientX, clientY) {
    mouse.x =  (clientX / window.innerWidth)  * 2 - 1;   // screen → normalized device coords
    mouse.y = -(clientY / window.innerHeight) * 2 + 1;
    raycaster.setFromCamera(mouse, camera);
    const hit = raycaster.intersectObjects(boardGroup.children, false)
                         .find(i => i.object.userData.square);
    return hit ? hit.object.userData.square : null;        // "e4" or null
}

board2dEl.addEventListener('click', (e) => {
    const cell = e.target.closest('.sq');
    if (cell) handleSquareClick(cell.dataset.square);      // same path as 3D
});

Replicate It Yourself

  1. Create a Firebase project. In the Firebase Console, add a web app, enable Realtime Database in locked mode (never test mode), and enable the Anonymous sign-in provider. Put the web config in firebase-config.js.
  2. Load Three.js and chess.js as classic scripts, then load your app as <script type="module"> and import the Firebase modular SDK from gstatic.com/firebasejs/<pinned version>/. Reference: Three.js docs, chess.js, Firebase via CDN.
  3. Build the board and pieces. 64 BoxGeometry tiles tagged with userData.square, and Staunton profiles passed to LatheGeometry. Reference: LatheGeometry.
  4. Write the rules first, then test them. Install a JDK and run cd rules-test && npm install && npm test. Every rule should have a test that fails when the rule is removed. Reference: Unit-test Security Rules.
  5. Develop against the emulators. firebase emulators:start --only auth,database, serve the folder on 127.0.0.1, and open the page with ?emu=1. The flag only works on a loopback host, so a crafted link can't redirect real users.
  6. Deploy rules, then the site. firebase deploy --only database from 3d-chess/, then push to GitHub Pages. Rules go first so the new client never runs against old rules. Reference: GitHub Pages.
