HOW IT'S BUILT

Subnet Trainer

A teaching tool, not a calculator. It makes you compute an IP's network range yourself using the block-size (magic-number) method, shows the human arithmetic, then drills you for speed.

Why This Exists (and how it differs from the CIDR Calculator)

The sibling CIDR Calculator hands you the answer instantly via bitwise math. That's a reference tool. This is a pedagogy tool: it teaches the mental method an engineer uses to read a subnet boundary by inspection — at a whiteboard, in an interview, or staring at a firewall rule with no calculator open. The Calculator answers "what is it?"; the Trainer answers "how do I work it out, fast?"

The Block-Size Method

The whole technique reduces to one observation: subnets repeat at a fixed interval — the block size — inside a single "interesting" octet. Find that interval and the rest is arithmetic.

  • 1. Block size = 256 − (subnet-mask octet value). A mask octet of 224 gives a block size of 32.
  • 2. Network = ⌊IP octet ÷ block⌋ × block. For 247 with block 32: ⌊247/32⌋=7, ×32 = 224.
  • 3. Next network = network + block.
  • 4. Broadcast = next network − 1.
  • 5. First usable = network + 1.
  • 6. Last usable = broadcast − 1.

The "interesting octet" is ⌊prefix ÷ 8⌋ — the octet where the mask transitions from ones to zeros.

The Edge Case That Breaks Naive Implementations

When prefix % 8 === 0 (i.e. /8, /16, /24), the mask lands exactly on an octet boundary. There is no partial octet — every octet is either fully locked (255) or fully free (0). A naive implementation that always looks for a "partial" mask octet falls apart here. This app treats it explicitly: the interesting octet's mask value is 0, so the block size is a full 256, the floor-division collapses to zero, and the network is simply "copy the locked octets, zero the free ones." The Learn view labels these as clean boundaries so the learner understands why there's no arithmetic to do.

Two Sources of Truth — and a Self-Check

The drill needs an answer key, and the Learn view needs to show human arithmetic. Those are computed two different ways:

  • Bitwise engine (computeFacts) — the authoritative answer, via the same ip & mask operations a router uses. Adapted from the CIDR Calculator's engine.
  • Block-size decomposition (decompose) — the human method, used only for the teaching display.

If those two ever disagreed, the app would teach a method that doesn't match its own answers. So a load-time self-check runs nine known cases (including the worked examples and the clean-boundary cases) and compares both paths against expected results. A mismatch logs a loud console.error. This is the honest cost of copying the math from the Calculator instead of sharing one module: the duplication is documented, and it's guarded.

A Bug Fixed Along the Way: /31

The Calculator computes first-usable as network + 1 unconditionally for anything below /32. For a /31 (RFC 3021 point-to-point link) that's wrong — both addresses are usable, so first-usable is the network address itself, not network+1. The Trainer fixes this (prefix >= 31 ? net : net + 1) because its Advanced drill tier tests /31 directly, and a teaching tool cannot ship a wrong answer key.

Drill Design: Don't Punish a Right Answer

The fastest way to destroy trust in a teaching tool is to mark a conceptually-correct answer wrong on a formatting technicality. Every answer is normalized before comparison — leading zeros, trailing whitespace, and case are stripped, and 192.168.050.224 compares equal to 192.168.50.224. For /31 and /32, the broadcast field accepts N/A, na, none, or blank. Wrong answers reveal the full worked solution — the same grid and step cards from Learn mode — so a miss becomes a lesson, not just a red X.

Streak Persistence

Best streak persists in localStorage under a namespaced key (subnet-trainer:best). Namespacing matters: every app on this hub shares one github.io origin, so an unprefixed key like best would collide with a neighbor. Reads and writes are wrapped in try/catch because private-browsing mode throws on setItem. No telemetry, no network — the CSP blocks connect-src entirely.

Security

  • No innerHTML. Every dynamic node — grid cells, step cards, feedback — is built with createElement + textContent. User input is parsed to integers before it ever touches the DOM.
  • Strict CSP. script-src 'self' on the app, 'none' on this page. No inline scripts, no external requests.
  • Validated input. Octet range (0–255) and prefix range (0–32) are checked before any computation; invalid input surfaces a plain-text error.

Stack

  • Vanilla JS, no libraries, no build step — one app.js loaded with defer.
  • CSS custom properties shared with the hub palette; the boundary octet is ringed in amber to draw the eye to where the work happens.
  • prefers-reduced-motion disables all transitions.
  • Two modes share one render path: the drill's "reveal solution" reuses the exact grid and step renderers from Learn mode.
