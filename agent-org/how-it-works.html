Agent Org — How It's Built

An org chart for a one-person team of AI agents, drawn from a single list of seats.

Overview

Agent Org shows who does what on a team of AI agents run by one person. Each seat states its job, the limit placed on it, and the phrase that calls it. The page is a static roster, not a live monitor, and it lists only the seats that are safe to show in public.

Tech Stack

HTML CSS JavaScript
  • HTML — the fixed frame: header, staff row, department grid, house rules and the sign-up form.
  • CSS — grid layouts that collapse to one column on a phone, with the kind of each seat carried by one custom property.
  • JavaScript — renders every seat from two arrays, then handles filtering, the detail panel and the copy button.

How Each Part Works

app.js — the roster is data

Every seat is one object. Adding an agent to the chart means adding one object, with no markup to copy.

{ id: "drill", ab: "RD", name: "Recall Drill", role: "Daily spoken practice",
  kind: "skill",            // agent | skill | routine | script | vacant
  say: "/drill-5",          // the phrase the copy button hands over
  does: "Picks five past tickets and grades spoken answers.",
  rule: "Edits only its own tracker." }   // the guardrail, shown on every seat

app.js — text is escaped before it is rendered

Seats are built as HTML strings, so every field passes through an escape function first. The roster is trusted today, but the habit keeps a future data source from injecting markup.

const esc = (s) => String(s).replace(/[&<>"]/g, (c) =>
  ({ "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;" }[c]));

index.html — a strict content security policy

Scripts load only from this site and the analytics host, so the page has no inline script at all. The form may post to one address and nowhere else.

script-src 'self' https://static.cloudflareinsights.com;
form-action https://api.web3forms.com;
base-uri 'none'; object-src 'none';

What Is Left Out, and Why

The private version of this chart also lists automations that touch personal messages, mail and money. A public inventory of those would tell a stranger exactly what to target, so they are not in the public data file. Publishing an architecture is useful. Publishing an attack surface is not.

Replicate It Yourself

  1. List every agent, skill and scheduled job you run. For each, write one sentence for what it does and one for what it must never do.
  2. Group them by the outcome they serve, not by the tool they use. Mark the seat that checks the others, even if it is empty.
  3. Put the list in an array and render it with a template string. Escape every field. Reference: MDN template literals.
  4. Decide what stays private before you publish, and keep it out of the public file entirely. Reference: MDN Content Security Policy.
