JWT Decoder — How It's Built

Client-side JSON Web Token inspector: decodes header, payload, and signature, and flags common security vulnerabilities.

Overview

JWT Decoder is a single-page app that decodes JSON Web Tokens entirely in the browser — nothing is sent to a server. Paste a JWT and instantly see the decoded header and payload with syntax highlighting, a claims summary table (subject, issuer, expiry, etc.), and the raw Base64URL-encoded signature. It actively checks for three security issues: the alg:none attack, expired tokens, and symmetric HMAC algorithms that are weaker than asymmetric alternatives. Built to demonstrate that JWT authentication — which is used in AWS Cognito, API Gateway authorizers, and virtually every modern API — is not magic; the token structure is transparent and inspectable.

What is a JWT?

A JWT is three Base64URL-encoded JSON objects joined by dots: header.payload.signature. The header declares the algorithm; the payload carries claims (facts about the user or session); the signature proves the token hasn't been tampered with. The header and payload are not encrypted — anyone who has the token can read them. Only the signature requires the secret key to produce or verify. 

// A JWT looks like this — three dot-separated Base64URL segments
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9        // header
.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkVkZGllIn0  // payload
.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c       // signature

// Decoded header:
{ "alg": "HS256", "typ": "JWT" }

// Decoded payload:
{ "sub": "1234567890", "name": "Eddie", "iat": 1516239022 }

How Each Part Works

Base64URL decoding

JWTs use Base64URL (RFC 4648 §5), which swaps + for - and / for _, and omits padding. The browser's atob() expects standard Base64, so you must normalize first. Wrapping with decodeURIComponent plus percent-encoding handles multi-byte UTF-8 characters in payloads (e.g., names with accents). 

function base64UrlDecode(str) {
  // 1. Normalize: Base64URL → standard Base64
  let s = str.replace(/-/g, '+').replace(/_/g, '/');
  // 2. Restore padding (atob requires multiple-of-4 length)
  while (s.length % 4 !== 0) s += '=';
  try {
    // 3. Decode bytes, then percent-encode each byte, then URI-decode the whole thing.
    //    This is the standard trick for handling UTF-8 in atob() output.
    return decodeURIComponent(
      Array.from(atob(s))
        .map(c => '%' + c.charCodeAt(0).toString(16).padStart(2, '0'))
        .join('')
    );
  } catch (_) {
    return null;  // malformed input — surface to user as an error
  }
}

DOM-based JSON syntax highlighting (XSS-safe)

The payload comes from user input, so setting innerHTML with it would be an XSS vulnerability. Instead, the highlighter walks the parsed JSON object and builds a tree of DOM nodes — one <span> per token type, each set via textContent. User data never touches the HTML parser. 

// Safe: build DOM nodes from the already-parsed object, never from the raw string.
// Every leaf value is set with .textContent — cannot inject HTML.
function renderJsonToNode(value, indent) {
  const frag = document.createDocumentFragment();
  const type = Array.isArray(value) ? 'array'
             : value === null       ? 'null'
             : typeof value;

  if (type === 'string') {
    const span = document.createElement('span');
    span.className = 'js';  // CSS class for string color
    span.textContent = JSON.stringify(value);  // re-serialize to add quotes safely
    frag.appendChild(span);
  } else if (type === 'number') {
    const span = document.createElement('span');
    span.className = 'jn';
    span.textContent = String(value);
    frag.appendChild(span);
  }
  // ... recurse for objects and arrays
  return frag;
}

Security check: alg:none (CVE-2015-9235)

The most famous JWT vulnerability: an attacker modifies the header to set "alg":"none", strips the signature, and submits the token. Vulnerable libraries — including early versions of node-jsonwebtoken — accepted unsigned tokens as valid because they trusted the header's algorithm claim over their own configuration. The fix is simple: the server must explicitly reject alg:none and never honor the algorithm specified in the token header. 

// Read the alg from the decoded header — not from user input string directly.
// typeof check prevents prototype pollution attacks on header.alg.
const alg = typeof header.alg === 'string' ? header.alg : '';

if (alg.toLowerCase() === 'none' || alg === '') {
  addAlert('danger', '⚠',
    'Security risk: alg is "none". This token has no cryptographic signature. ' +
    'Any server that accepts alg:none tokens is trivially forgeable.');
}

Security check: token expiry

The exp claim is a Unix timestamp (seconds since epoch). Comparing it against Date.now() / 1000 tells us if the token has expired. This is purely informational in the decoder — real enforcement happens server-side. The check also flags nbf (not-before), which is the lesser-known sibling claim that prevents a token from being used before a specified time. 

const now = Math.floor(Date.now() / 1000);  // current time in Unix seconds

// exp: token must be rejected after this timestamp
if (typeof payload.exp === 'number' && now > payload.exp) {
  const minsAgo = Math.round((now - payload.exp) / 60);
  addAlert('warn', '⏰', `Token expired ${minsAgo} minutes ago.`);
}

// nbf: token must not be accepted before this timestamp
if (typeof payload.nbf === 'number' && now < payload.nbf) {
  addAlert('warn', '⏳', 'Token is not yet valid — nbf is in the future.');
}

JWT in the Wild — Where You'll See This

  • AWS Cognito — issues JWTs (access, ID, refresh tokens) for user pools. Lambda authorizers validate them using the Cognito JWKS endpoint.
  • API Gateway authorizers — Lambda authorizers receive the JWT from the Authorization header and return an IAM policy. The token's sub or custom claims drive authorization decisions.
  • OIDC / IAM federation — AWS STS AssumeRoleWithWebIdentity exchanges an OIDC JWT for temporary AWS credentials. The JWT's aud and iss claims are validated by STS.
  • Kubernetes service accounts — k8s mounts a projected service account token (a JWT) into every pod. Used by the AWS EKS Pod Identity and IRSA mechanisms.

Replicate It Yourself

  1. Understand the wire format. Split the raw JWT string on '.' — you always get exactly 3 parts. Parts 0 and 1 are Base64URL-encoded JSON. Part 2 is the signature bytes (also Base64URL), which you display but cannot verify without the key. Reference: RFC 7519 — JSON Web Token.
  2. Write the Base64URL decoder. Swap -/_ back to +//, re-pad to a multiple of 4, then call atob(). Wrap with decodeURIComponent and percent-encoding to handle UTF-8. Reference: MDN atob().
  3. Never set innerHTML with decoded content. The payload is user-supplied. Build your JSON display using document.createElement + textContent. Every value from the token must go through textContent, never innerHTML. Reference: OWASP DOM XSS Prevention Cheat Sheet.
  4. Check exp against Date.now(). Convert Date.now() to Unix seconds by dividing by 1000. If now > payload.exp, the token is expired. Always use typeof payload.exp === 'number' before comparing — undefined > n is false in JS, which silently skips the check.
  5. Flag alg:none. Read header.alg after parsing the decoded JSON — never from the raw Base64 string. Reject or warn if it equals "none" or is absent. This is the single most important JWT security check. Reference: Auth0 — Critical vulnerabilities in JWT libraries (2015).
  6. Deploy to GitHub Pages. Push to main, go to repo Settings → Pages → Source: Deploy from branch → main / (root). Reference: GitHub Pages docs.
