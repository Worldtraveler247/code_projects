Origin Trace — How It's Built

IT career trajectory catalog: 6 entry-level role paths, BLS salary data, cert costs, and an SVG career DAG.

Overview

Origin Trace is a static multi-page app that maps six entry-level IT career starting points — Help Desk, NOC Technician, Cloud Support, GRC Analyst, SOC Analyst, and Junior Network Admin — for people with a degree and Network+/Security+ who are breaking into tech. Each role has a detailed page with BLS salary data, required certifications with real costs, a timeline to first job, and a DAG (directed acyclic graph) showing which roles lead to which over a 3–5 year career arc. All data lives in a single roles.json file that the frontend fetches and renders dynamically.

Tech Stack

HTML CSS JavaScript JSON SVG
  • HTML — four page templates: landing grid, role detail, career atlas map, SVG DAG viewer
  • CSS — dark card grid, role-card hover animations, responsive layout
  • JavaScript — fetch('data/roles.json') and dynamic card/content rendering, URL parameter routing
  • JSON — single source of truth for all role data: titles, taglines, salaries, certs, next_moves edges
  • SVG — the career DAG rendered as SVG paths with arrow markers; nodes are role names, edges are career transitions

How Each Part Works

js/main.js — fetch and render role grid

The landing page fetches data/roles.json on load, then loops over the roles array to build a card for each role. Each card is a plain <a> element pointing to role.html?role=slug. Filter chip clicks filter the visible cards by the data-track attribute without re-fetching the JSON. 

async function renderGrid() {
  const grid = document.getElementById('role-grid');
  let data;
  try {
    const res = await fetch('data/roles.json');
    if (!res.ok) throw new Error('HTTP ' + res.status);
    data = await res.json();
  } catch (err) {
    // Show an error message in the grid if fetch fails
    const msg = document.createElement('p');
    msg.textContent = 'Could not load role data. Make sure data/roles.json is present.';
    grid.appendChild(msg);
    return;
  }

  // Build one card per role — DOM creation, no innerHTML template strings
  data.roles.forEach((role, idx) => {
    const grad = CARD_GRADIENTS[role.slug] || { a: '#0a1520', b: '#0d2030' };
    grid.appendChild(buildCard(role, grad, idx));
  });

  setupScrollReveal();
}

function buildCard(role, grad) {
  const a = document.createElement('a');
  a.className = 'role-card';
  // URL parameter routing: role.html reads ?role=slug via URLSearchParams
  a.href = 'role.html?role=' + encodeURIComponent(role.slug);
  a.dataset.track = role.track || 'all'; // used by filter chip JS
  // ... attach visual and body children
  return a;
}

role.html — URL parameter routing

The role detail page is a single HTML file that reads which role to display from the URL query string using new URLSearchParams(window.location.search).get('role'). It then fetches roles.json, finds the matching entry, and populates the page. This means there are no per-role HTML files to maintain — just one template and one data file. 

// role.html inline script (simplified)
const params = new URLSearchParams(window.location.search);
const slug   = params.get('role');  // e.g. "soc-analyst"

fetch('data/roles.json')
  .then(r => r.json())
  .then(data => {
    const role = data.roles.find(r => r.slug === slug);
    if (!role) { document.title = '404'; return; }

    document.title = role.title + ' — Origin Trace';
    document.getElementById('role-title').textContent = role.title;
    document.getElementById('role-tagline').textContent = role.tagline;
    // populate salary, certs, timeline sections...
  });

js/dag.js — SVG career DAG

The DAG view reads next_moves arrays from roles.json to build directed edges. Each role is a node; each next_moves entry is an edge. Nodes are positioned on a grid, then SVG <line> elements with <marker> arrowheads connect them. The entire graph is generated in JS and inserted into an SVG element. 

// Simplified DAG rendering (from js/dag.js)
// roles.json has: { "slug": "help-desk", "next_moves": ["noc-technician", "cloud-support"] }

function renderDAG(roles) {
  const svg = document.getElementById('dag-svg');
  const positions = layoutNodes(roles);  // assign x,y grid positions

  // Draw edges first (so they appear behind nodes)
  roles.forEach(role => {
    (role.next_moves || []).forEach(targetSlug => {
      const from = positions[role.slug];
      const to   = positions[targetSlug];
      if (!from || !to) return;

      const line = document.createElementNS('http://www.w3.org/2000/svg', 'line');
      line.setAttribute('x1', from.x);
      line.setAttribute('y1', from.y);
      line.setAttribute('x2', to.x);
      line.setAttribute('y2', to.y);
      line.setAttribute('marker-end', 'url(#arrow)');  // arrowhead marker
      line.setAttribute('stroke', '#4af7ff');
      svg.appendChild(line);
    });
  });
}

Replicate It Yourself

  1. Design your JSON schema. Decide what each role entry needs: slug, title, tagline, track, icon, salary data, cert list, and next_moves: [slugs]. A flat array of role objects is all you need.
  2. Build the landing page with a fetch + render loop. fetch('data/roles.json').then(r => r.json()).then(data => data.roles.forEach(buildCard)). Set data-track attributes on cards for filter chip filtering. Reference: MDN Fetch API.
  3. Add URL-parameter routing for the detail page. Use new URLSearchParams(window.location.search).get('role') to get the slug, then find the matching role in the JSON. Reference: MDN URLSearchParams.
  4. Add filter chips. Each chip has a data-track attribute. On click, use document.querySelectorAll('.role-card') and set display: none on cards whose dataset.track doesn't match.
  5. Render the SVG DAG. Use document.createElementNS('http://www.w3.org/2000/svg', 'line') to draw edges. Define an SVG <marker> with a triangle path for the arrowhead. Layout nodes on a grid by hand or with a simple force-directed algorithm. Reference: MDN SVG marker element.
  6. Deploy to GitHub Pages. Push to main, go to repo Settings → Pages → Source: Deploy from branch → main / (root). Reference: GitHub Pages docs.
