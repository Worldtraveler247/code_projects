HOW IT'S BUILT

CIDR Calculator

Client-side subnet math using bitwise arithmetic — the same operations a router performs when making forwarding decisions.

Why This Tool Exists

Every AWS VPC, security group rule, NACL, and route table entry uses CIDR notation. When you write 10.0.1.0/24 as an ingress rule, you need to know that means 254 usable hosts from 10.0.1.1 to 10.0.1.254. This tool makes that explicit and shows the underlying bit math.

The Core Math

Every calculation reduces to four bitwise operations on 32-bit integers:

// Convert dotted-decimal to 32-bit integer
const ipInt = (a << 24) | (b << 16) | (c << 8) | d;

// Build the subnet mask from the prefix length
const mask = prefix === 0 ? 0 : (0xFFFFFFFF << (32 - prefix)) >>> 0;

// Network address — zero out host bits
const network = (ipInt & mask) >>> 0;

// Broadcast — set all host bits to 1
const broadcast = (network | (~mask >>> 0)) >>> 0;

The >>> 0 casts the result to an unsigned 32-bit integer. JavaScript's bitwise operators work on signed 32-bit integers, so without this cast, addresses above 127.255.255.255 produce negative numbers — a silent bug that breaks every calculation for the top half of the IPv4 space.

Host Count

A /prefix block has 2^(32 - prefix) total addresses. Subtract 2 for the network and broadcast addresses to get usable hosts. Edge cases:

  • /31 — RFC 3021 point-to-point links. Both addresses are usable (no broadcast). Common on router-to-router links.
  • /32 — Single host route. Used in AWS security groups to whitelist one specific IP.
  • /0 — The entire IPv4 space (4,294,967,296 addresses). Represents the default route in routing tables.

RFC 1918 Detection

Three private address ranges defined in RFC 1918 are never routed on the public internet. Detection is a bitmask comparison:

function isPrivate(n) {
    return ((n & 0xFF000000) >>> 0) === 0x0A000000   // 10.0.0.0/8
        || ((n & 0xFFF00000) >>> 0) === 0xAC100000   // 172.16.0.0/12
        || ((n & 0xFFFF0000) >>> 0) === 0xC0A80000;  // 192.168.0.0/16
}

AWS VPCs must use RFC 1918 space. If you try to create a VPC with a public IP range, the console rejects it.

AWS VPC CIDR Constraints

AWS enforces hard limits on VPC CIDR blocks: minimum /28 (16 addresses, 11 usable after AWS reserves 5 per subnet) and maximum /16 (65,536 addresses). The calculator flags this range automatically — a /8 or /29 badge change is an immediate signal that the CIDR won't work as a VPC block without modification.

Subnet Splitter

Given a parent block and a target prefix, the number of subnets is 2^(target - parent). Each subnet starts at an offset of 2^(32 - target) addresses from the previous one:

const count  = 2 ** (targetPrefix - parentPrefix);
const size   = 2 ** (32 - targetPrefix);
const subnets = Array.from({length: count}, (_, i) =>
    toIP((netInt + i * size) >>> 0) + '/' + targetPrefix
);

This is exactly how AWS auto-assigns subnets when you use the VPC wizard's "divide into subnets" feature.

Security

  • No innerHTML on user input. All dynamic content is built with createElement + textContent. User-supplied CIDR strings are parsed to integers before any DOM interaction — the string never reaches the DOM directly.
  • No external requests. Everything runs client-side. The CSP blocks connect-src entirely.
  • Input validation. Octet range (0–255) and prefix range (0–32) are validated before any calculation runs. Invalid input surfaces a plain-text error message, never HTML.

Stack

  • Vanilla JS — no libraries. The math is three bitwise operators; a library would add more complexity than it removes.
  • CSS custom properties for the shared color palette with the hub.
  • Sticky nav with backdrop-filter: blur so the title stays readable while scrolling through long subnet lists.
  • prefers-reduced-motion disables all transitions.
