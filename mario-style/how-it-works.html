Galactic Runner — How It's Built

Twilight side-scrolling platformer with parallax mountains, gravity physics, and neon platforms.

Overview

Galactic Runner is a horizontal platformer built in pure JavaScript and Canvas. The player runs through two procedurally themed stages, jumping between floating neon platforms while avoiding patrol and flying enemies. The background uses a three-layer parallax effect — stars, back mountains, front mountains — each scrolling at a different rate to create depth. Gravity and jump physics are implemented from scratch with per-frame velocity accumulation. Mobile players get a pointer-based joystick and jump button.

Tech Stack

HTML CSS JavaScript Canvas API
  • HTML — one <canvas> element, mobile control overlays, HUD divs
  • CSS — responsive canvas scaling, joystick and jump button layout
  • JavaScript — gravity physics, parallax scrolling, platform collision, enemy AI, coin collection
  • Canvas API — all rendering: backgrounds, platforms, player, enemies, particles, HUD

How Each Part Works

game.js — gravity and jump physics

The player has a vertical velocity vy. Every frame, GRAVITY (0.55 px/frame²) is added to vy, pulling the player down. On jump, vy is set to a large negative value (upward). When the player's feet touch a platform, vy is zeroed and grounded is set to true. This simple model produces believable arcing jumps. 

const GRAVITY  = 0.55;  // px added to vy every frame
const FRICTION = 0.82;  // horizontal slowdown when no key held

// Inside the player update loop each frame:
player.vy += GRAVITY;         // gravity accumulates downward velocity
player.y  += player.vy;      // apply velocity to position
player.vx *= FRICTION;        // friction decelerates horizontal movement
player.x  += player.vx;

// jump() is called on Space / ArrowUp / jump button press:
function jump() {
    if (!player.jumping && player.grounded) {
        player.jumping = true;
        player.grounded = false;
        player.vy = -player.speed * 2.9;  // large negative vy = upward launch
    }
}

game.js — parallax background layers

Three background layers — stars, back mountains, front mountains — each have a scroll speed proportional to their "distance." Stars scroll at 12%, back mountains at 20%, front mountains at 35% of the camera speed. Each layer is drawn translated by -cameraX × speed, creating the illusion of depth without 3D rendering. 

// Camera follows the player: cameraX = player.x - canvas.width * 0.25
// Parallax: each layer moves at a fraction of the camera speed

function drawStars(cameraX) {
    stars.forEach(s => {
        // Stars at 12% speed appear very far away
        const sx = ((s.x - cameraX * 0.12) % WORLD_W + WORLD_W) % WORLD_W;
        ctx.beginPath();
        ctx.arc(sx, s.y, s.r, 0, Math.PI * 2);
        ctx.fillStyle = `rgba(255,255,255,${0.3 + 0.5 * Math.sin(t * s.speed + s.phase)})`;
        ctx.fill();
    });
}

function drawMtnBack(cameraX) {
    mtnBack.forEach(m => {
        // Back mountains at 20% speed — closer than stars
        const mx = ((m.x - cameraX * 0.20) % WORLD_W + WORLD_W) % WORLD_W;
        ctx.beginPath();
        ctx.moveTo(mx, canvas.height);
        ctx.lineTo(mx + 60, canvas.height - m.h);
        ctx.lineTo(mx + 120, canvas.height);
        ctx.fillStyle = stage.mtnBackCol;
        ctx.fill();
    });
}

game.js — platform collision

Platform collision uses an AABB (axis-aligned bounding box) overlap test. The key insight is checking the previous Y position to determine which face the player hit — only landing on the top of a platform sets grounded, preventing the player from sticking to the side or bottom. 

function overlap(ax, ay, aw, ah, bx, by, bw, bh) {
    return ax < bx + bw && ax + aw > bx && ay < by + bh && ay + ah > by;
}

stage.platforms.forEach(plat => {
    if (overlap(player.x, player.y, player.w, player.h,
                plat.x, plat.y, plat.w, plat.h)) {
        // Only land on top if player was above the platform last frame
        // (prevY + player.h <= plat.y) means feet were above the platform top
        if (player.vy >= 0 && prevY + player.h <= plat.y + 4) {
            player.y      = plat.y - player.h;  // snap feet to platform top
            player.vy     = 0;
            player.jumping  = false;
            player.grounded = true;
        }
    }
});

Replicate It Yourself

  1. Create a canvas and a responsive resize function. Set a fixed logical size (e.g., 480×310) and use CSS to scale it to the viewport with canvas.style.width. Call fitCanvas() on window.resize. Reference: MDN Canvas API.
  2. Build the player object with vy. Start with player = { x, y, vx: 0, vy: 0, grounded: false }. Each frame: vy += GRAVITY, y += vy. For jump: if grounded, set vy = -jumpStrength.
  3. Implement three parallax background layers. Store stars, back mountains, and front mountains in separate arrays. Draw each at x - cameraX × layerSpeed, using modulo wrapping to tile infinitely.
  4. Draw back-to-front. Render in this order: sky gradient, stars, back mountains, front mountains, platforms, coins, enemies, player, HUD. This prevents foreground elements from being covered by background layers.
  5. Add platform collision with face detection. Track the player's Y position from the previous frame. In the overlap test, only set grounded = true and snap Y if the player was above the platform top in the previous frame.
  6. Deploy to GitHub Pages. Push to main, go to repo Settings → Pages → Source: Deploy from branch → main / (root). Reference: GitHub Pages docs.
